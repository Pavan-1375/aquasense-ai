# AquaSense AI Evidence Pack

## Hardware evidence

The current prototype uses an ESP32, an ultrasonic distance sensor, and an SSD1306 128×64 OLED.

| Component | Connection | Purpose |
|---|---|---|
| Ultrasonic trigger | ESP32 GPIO 5 | Starts a distance measurement |
| Ultrasonic echo | ESP32 GPIO 18 | Receives the return pulse |
| OLED SDA | ESP32 GPIO 21 | I²C data |
| OLED SCL | ESP32 GPIO 22 | I²C clock |
| OLED VCC/GND | Board supply and ground | Display power |
| OLED address | `0x3C` | I²C device address |

Important: verify the actual HC-SR04 echo voltage protection before powering the circuit. A 5 V echo signal must not be connected directly to an ESP32 input unless the sensor/level-shifting arrangement is confirmed safe.

The firmware and an illustrative wiring diagram are included in this pack. A photograph of the assembled circuit is not included because it must be an actual photograph of the student's hardware, not a generated image.

## Physical measurement process

1. Mount the ultrasonic sensor above the water surface.
2. Keep the sensor aligned vertically with the surface.
3. At startup, collect the reference distance using repeated samples.
4. Reject invalid or widely dispersed readings.
5. Use the median distance for each cycle.
6. Smooth the measured height and display it on the OLED.
7. Send the JSON packet over USB serial.
8. The laptop serial bridge forwards it to the backend.

The current ESP32 prototype measures distance/water level only. pH, TDS, turbidity, and temperature are entered manually or supplied by external sources.

## Machine-learning evidence

### Active four-parameter profile

Features, in order:

```text
pH, TDS_mg_L, turbidity_ntu, temperature_c
```

Model task: formula-assisted screening classification.

Classes: Excellent, Good, Poor, Very Poor, Unsuitable.

Candidate algorithms:

- Logistic Regression baseline
- Random Forest
- Extra Trees
- XGBoost

Selection metric: macro-F1 using stratified five-fold cross-validation.

Selected profile: Extra Trees, because it produced the strongest development macro-F1 among the candidates.

Important limitation: labels are generated by the project-defined formula. The metrics measure agreement with those labels, not laboratory-confirmed potability or health safety.

### Offline five-parameter profile

Features:

```text
pH, EC, TDS, hardness, chloride
```

This model is an offline comparative experiment. It is not used by the active four-parameter sensor path.
